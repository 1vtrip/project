# cpp_core — заметки для команды

## Что делает
`schedule_engine.exe <номер_группы>` — ходит в API БГУИР, получает расписание,
фильтрует на сегодня и текущую неделю, печатает результат в stdout.

## Почему WinHTTP, а не curl/cpr
Изначально HTTP-запросы были на `cpr` (обёртка над `curl`). Но сборка `curl`
из исходников через `FetchContent` под MinGW падала с ошибкой
`"no non-blocking method was found/used/set"` в `lib/nonblock.c` — это
известная проблема детекта сокетных функций curl'а конкретно в связке
MinGW + CMake. Чтобы не тратить время на починку чужого build-скрипта,
HTTP-запросы переписаны на **WinHTTP** — это API из состава Windows SDK,
уже скомпилированное, просто линкуется (`-lwinhttp`), собирать ничего
не нужно.

**Важное следствие: модуль стал Windows-only.** WinHTTP не работает на
Linux/macOS. Если кому-то из команды нужно собирать на другой ОС —
возвращаемся к `curl`/`cpr` (или берём `curl` готовым пакетом из
системного менеджера пакетов, а не собираем из исходников) и меняем
только функцию `HttpGet` в `main.cpp` — остальной код (парсинг JSON,
фильтрация по дню/неделе, формат вывода) трогать не придётся.

## Контракт вывода (для Студента 3, integration/ipc_bridge.py)
- Успех, есть пары: по одной строке на занятие, поля через `|`:
  `startTime|endTime|subjectFullName|lessonType|auditories|teachers|subgroup|note`
  - `auditories` и `teachers`, если их несколько — через запятую внутри поля.
  - `subgroup`: `0` — общее занятие, `1`/`2` — для конкретной подгруппы.
- Пар на сегодня нет: одна строка `NO_LESSONS`.
- Ошибка: stdout пустой, текст ошибки в stderr, код возврата процесса `1`.
  **Важно:** ipc_bridge.py должен проверять return code, а не только пытаться
  распарсить stdout.

## Допущения, которые нужно проверить одним реальным запуском
Я не подтверждал точную схему JSON боевым запросом к `iis.bsuir.by`, а
опирался на документированную структуру этого API. Собери проект и запусти:

```powershell
.\schedule_engine.exe <номер_твоей_группы>
```

и сверь с реальным выводом. Вероятные места расхождений — те же, что и
раньше:
1. **Обёртка JSON** — код поддерживает `{"schedules": {"Понедельник": [...]}}`
   и плоский `{"Понедельник": [...]}`. Если структура другая — смотри
   `FindDayLessons` в main.cpp.
2. **Названия полей занятия** — `subjectFullName`/`subject`,
   `startLessonTime`/`endLessonTime`, `weekNumber` (массив чисел 1-4),
   `numSubgroup`, `note`, `lessonTypeAbbrev`, `auditories` (массив строк),
   `employees` (массив объектов с `firstName`/`lastName`/`middleName`).
   Для отладки можно временно напечатать `resp.body` целиком перед
   `json::parse` в main.cpp.
3. **Эндпоинт текущей недели** `/api/v1/schedule/current-week` — если он не
   существует/другой формат, код тихо переключается на расчёт недели от
   1 сентября текущего учебного года (`ComputeFallbackWeek`). Если
   официальный алгоритм подсчёта недели отличается — поправь эту функцию.

## Сборка
```powershell
cd cpp_core
mkdir build
cd build
cmake ..
cmake --build .
```
Зависимость (`nlohmann/json`, header-only) подтягивается автоматически
через `FetchContent`. `winhttp` уже есть в составе Windows/MinGW, ничего
дополнительно ставить не нужно.
